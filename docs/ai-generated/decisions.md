# 设计决定

## 2026-10-31：基线 ②（联合深度）

基线 ② 见提案 7.2：在 Stage 1 模型上加一个 disparity 通道，与 RGB 用同一个噪声水平一起去噪，训练时 chunk 内噪声统一（s=0）。

1. **disparity 作为第 17 个 latent 通道。** 放在 latent 网格上（60×104，每个值对应 8×8 像素），和 16 个 RGB 通道拼成一个张量。加噪、采样器、CFG、KV refresh 都不用改，只改模型，以及 VAE 解码前切掉这个通道。
   - 与提案 4.3 不同：新增 `disp_embed = Conv3d(1→1536, 1×2×2)` 和 `disp_head = Linear(1536→4)`，都零初始化。③ 需要每个 token 一个深度值时，取 2×2 的最大值。（已被 2026-11-01「disparity 改为稠密」取代）
2. **loss = RGB 项 + λ·disparity 项，λ = 1。** 两项各自在自己的元素上取 MSE 均值，所以每个 token 的 RGB（64 个值）和 disparity（4 个值）权重相同。两项分开记日志；按噪声水平分档的统计以后再加。
3. **disparity 缩放 a = 1（提案默认 2）。** 网络输入为 a·(2d−1)，d ∈ [0,1]。每个 token 有 4 个独立加噪的 disparity 值，深度在 2×2 内变化小，模型平均后有效幅度约翻倍，所以这里的 a=1 约等于提案的 a=2。（已被 2026-11-01「disparity 改为稠密」取代）

## 2026-11-01：SpatialVID 数据格式（数据、模型、评测三条线共用）

数据线负责写 LMDB，模型线负责读，评测线生成视频时输入的相机位姿也按这里的规则来。这一节一改，三条线要一起改。标【待定】的项由括号里写的那条线定下来再填；全部填完之前，不写正式的 LMDB。

**片段**

1. 训练片段长 45 个像素帧，即 12 个 latent 帧、3 个 chunk；16 fps，480×832（提案 6.2）。
   - **重采样**：每段只取一个窗口，从第 0 个标注帧（即原视频第 0 帧）开始。输出第 j 个像素帧取原视频第 round(j·fps/16) 帧，不做帧间混合；fps 用元数据的值（group_0001 抽 300 个视频，与 mp4 容器差 ≤ 0.07，帧数差 ≤ 2）。位姿在这一帧的实际时刻插值（相机位姿第 1 条），深度取离这一时刻最近的标注帧（disparity 第 4 条）。
   - **跳过标注跨度不到 2.75 秒的段**，否则最后一个位姿要外推。group_0001 有 90.7% 够长。同一段里切多个窗口会高度相关，所以宁可多下几个 group，也不在一段里切多个窗口。
   - **裁剪**：1280×720 → 832×480 要裁掉 2.5% 的宽度：居中裁成 1248×720（左右各 16 像素），再用面积插值（`cv2.INTER_AREA`）按 2/3 缩放。内参换算：fx/W ← fx/W·1280/1248，cx/W ← (cx/W·1280 − 16)/1248（主点在中心时仍是 0.5），fy/H、cy/H 不变。
   - **深度图**（328×584，宽高比 1.780）用同一个归一化窗口：输出像素 (u, v) 取深度图第 ⌊(16 + 1.5(u+0.5))/1280·584⌋ 列、第 ⌊(v+0.5)/480·328⌋ 行（最近邻），与 RGB 逐像素对齐。算 P₉₀ 用的「裁剪后原始分辨率」是中心落在窗口内的深度像素。
2. 评测线现在按 20 个 latent 帧（77 个像素帧）生成，见 `tools/eval/worldscore/_common.py` 里的 `NUM_LATENT_FRAMES`，和训练长度不同。提案 6.2 允许评测长度和训练长度分开定，但所有方法必须一致；评测长度在提案 7.1 里定，不在这一节定。
3. 训练集和验证集分成两个 LMDB：`spatialvid/train` 和 `spatialvid/val`。验证集 8 段，两个集合不能出自同一个源视频。
   - 训练集取 group_0001–0003 的全部可用段（一条 run 约 12000 个样本，约 3 个 group），验证集 8 段从 group_0004 挑，并排除与训练集同源视频的段。
4. **选片只做硬性剔除，不排序**（2026-11-01 用户确认）：去掉动态像素占比过高的段、几乎不动的段（`moveDist` 接近 0），每个源视频最多取若干段；阈值由数据线在 group_0001 上看分布后定。提案 6.4 的"按视差代理量排序"等数据有富余再做。

**LMDB 键**：沿用 `tools/data/wan21/build_worldplaygen_lmdb.py` 的写法，每个键有一个 `<key>_shape`，每个样本有一个 `<key>_<i>_data`。

| 键 | 每个样本的形状 | dtype | 内容 |
|---|---|---|---|
| `latents` | (12, 16, 60, 104) | float16 | Wan VAE latent |
| `prompts` | 标量 | str | caption |
| `intrinsics` | (4,) | float32 | [fx/W, fy/H, cx/W, cy/H]，W、H 是裁剪和缩放之后的 832、480 |
| `poses` | (12, 7) | float32 | w2c，OpenCV 坐标系，[tx,ty,tz,qx,qy,qz,qw] |
| `disparity` | (12, 1, 240, 416) | float16 | d ∈ [0,1]，1 最近，0 无穷远 |
| T5 嵌入 | 【待定·模型线】 | | |

**相机位姿**

1. 第 k 个 latent 帧用第 4k 个像素帧的位姿，并对齐到第 0 个像素帧，所以第 0 个位姿是单位阵。评测线 `worldscore_to_minwm_poses` 的取法（`c2w[4·arange(F)]`，对齐到第一帧）与此相同。
   - SpatialVID 只在标注帧上有位姿：`indexes.txt` 第 1 列是标注帧在原视频里的帧号，24/30/50/60 fps 的视频分别每 4/5/10/11–12 帧标一次，约每 0.17–0.2 秒一个。第 4k 个像素帧在 16 fps 下是 k/4 秒，一般落在两个标注帧之间。**按时间（原视频帧号 / fps）在相邻两个标注帧之间插值：平移线性插值，旋转 slerp。** 不取最近帧，因为最近帧的时间误差最多约 0.1 秒，会直接变成相机控制误差。
2. 内参每段只存一个，数据集类会把它铺到所有帧。取第 0 个像素帧的内参：group_0001 的 5000 段里，每段的内参逐帧完全相同，主点都在图像中心，像素都是方的（以像素计 fx = fy，归一化后 fy/H = (16/9)·fx/W）。预处理时检查这一点，遇到逐帧不同的段就报错，不静默取第 0 帧。
   - 不同段的焦距差别很大：fx/W 的 P1–P99 是 0.34–1.62，所以内参必须逐段存，不能用一个全局值。
   - 基座只见过一种内参：fx/W ≈ 0.505，水平视场约 89°（`build_worldplaygen_lmdb.py:145`）。PRoPE 直接用 K，所以离 0.505 远的片段对基座是新的域；group_0001 上 fx/W 的中位数是 0.749（水平视场 67°），只有 17% 在 0.505 的 ±10% 以内。**不按接近基座筛选，保留自然分布**（2026-11-01 用户确认）：评测相机（WorldScore，fx/W ≈ 0.98）本身就离基座很远，按基座筛反而离评测更远；逐段真实内参让 PRoPE 学会用 K。只去掉极端长焦的尾巴：**裁剪后 fx/W > 1.5（水平视场 < 37°）的段跳过**，group_0001 去掉 1.2%。这条尾巴大多不是真长焦，而是焦距估错了：抽看缩略图，fx/W > 2 的几段是行车记录仪、GoPro、过山车这类广角画面，却被估成 8°–28° 的视场；1.2–1.5 之间的画面看着大多合理。内参错了，位姿多半也不可靠。更严的 1.2 会去掉 3.6%。
3. 平移缩放：所有平移（单位是米）乘同一个全局常数 1.54，使运动片段每个 latent 帧的平移中位数（0.052 m）对上基座的 0.08 单位（提案 6.2）。
   - 不用逐段系数（× 第一个 chunk 的 P₉₀ disparity）：在 group_0001（5000 段）上它没有让各段的平移更集中，运动片段 std(log10) 从 0.292 变成 0.307；各段 P₉₀ 只差 1.8 倍，而平移差 6 倍。评测时 WorldScore 也不提供深度，逐段系数用不上。
   - 评测线的 `translation_scale` 保持 1.52，不改。它把 WorldScore 的轨迹单位换算到基座步长：push_in 走 1 个单位，乘 1.52 正好是 19 步 × 0.08（`tools/eval/worldscore/prepare.py`）。两个系数的目标相同，都是让模型看到约每个 latent 帧 0.08 的步长，但换算的是两种不同的单位，数值接近只是巧合。
   - 这个系数不要叫 c，术语表里的 c 是"进度参数"。
4. **评测时的内参【待定·评测线】。** 现在 minWM 推理一律用 fx = fy = 0.5（`minwm/processors/camera.py` 的 `make_camera_tensors` 默认值，没有 config 覆盖），和基座训练用的 fx/W = 0.505、fy/H = 0.898 不一致（fy 差约 2 倍）。WorldScore 的 `config/base_config.yaml` 定 `focal_length: 500`，它的 3D 适配器按 512×512 设主点，按此 fx/W ≈ 0.98、水平视场约 54°，落在 SpatialVID 的第二个峰（0.8–1.0）里；这个分辨率假设还要核实。**规则：模型拿到的 K 永远来自当前数据本身**（2026-11-01 用户确认）。训练用 SpatialVID 每段的真实内参；评测用评测数据的相机，即 WorldScore 的 focal_length 按裁剪到 480×832 后换算，不用占位的 0.5，也不用基座的 0.505。所有方法（含原版 minWM）都用这同一个 K。
5. 转换完用 `tools/data/wan21/check_dataset_bev.py` 把轨迹和视频画在一起检查。

**disparity**（2026-11-01 改为稠密，理由见末尾一节）

1. **EXR 存的就是 1/z，直接用，不再取倒数。** SpatialVID 的深度 EXR 只有一个 `Z` 通道，float16，值是逆深度（官方 `utils/read_depth.py` 用 1/Z 换回深度）。下面公式里的 1/z 就是这个值。
   - **远处已截在 200 m**（逆深度 0.005），天空大多停在这个值上，所以不另设 z_max。天空不特殊处理，按下一条的公式截断。
   - **负值是天空的另一种写法，按最远处理，算 loss。** group_0001 抽 150 段、8359 帧：负值占像素 6.1%，出现在 33% 的帧里；几乎全在画面上半部，值几乎都是 −0.01；有负值的帧都没有 200 m 平台，没有负值的帧有 55% 有，说明两者是天空的两种写法；负值周围的有效像素在该帧最远的 3% 里；抽 6 帧和 RGB 对照，负值正好盖住天空。预处理先把负值和 0（像素占比约 1e-8）都换成 0.005，与另一种写法一致，再算 P₉₀ 和 d。
   - **NaN、inf 记为无效、不算 loss。** 抽样里没有出现，但官方读取代码在 EXR 读不出来时会返回全 NaN 的帧。预处理统计每段的无效像素，写进日志。
   - **近大远小检查**：每段统计画面最下 10% 行的逆深度中位数大于最上 10% 行的帧占多少，不到一半就跳过这段并记日志；一个 group 里跳过的超过 5% 就报错停下，因为那更可能是存储格式和这里假设的不一样。group_0001 抽样里 99.3% 的段通过；唯一没通过的一段是仰拍廊桥顶棚，画面上方确实更近，深度是对的，这种误伤可以接受。
2. 因果归一化：d = clip(0.9·(1/z)/P₉₀, 0, 1)。P₉₀ 是第一个 chunk 内 disparity 的 90% 分位数（不排除天空），后续 chunk 沿用同一个 P₉₀（提案 6.2）。具体在分给 latent 帧 0–3 的那 4 张深度帧上算（见第 4 条），用裁剪后、缩放前的原始分辨率，与 LMDB 里实际存的标签同一批帧。
3. 空间：缩放到 480×832（最近邻），每 2×2 像素做高分位聚合（90%，`interpolation="higher"`），得到 240×416。③ 每个 token 的 d 取它 64 个值的 90% 分位。
4. 时间：第 k 个 latent 帧取时间上离 k/4 秒（第 4k 个像素帧）最近的深度帧，不插值，误差最多约 0.1 秒。深度只在标注帧上有：zip 里第 i 个文件（文件名就是 `indexes.txt` 第 0 列的 i）对应原视频第 `indexes[i,1]` 帧；group_0001 的 5000 段全部核对过，深度帧数、位姿条数、内参条数都相等。
5. LMDB 里存 γ=1 时的 d，γ 次幂在训练端做。

**T5 嵌入**【待定·模型线】：Wan 的 `text_len=512`、`text_dim=4096`（`minwm/modeling/adapter.py:53`）。键名、存不存补齐到 512 的部分、dtype 由模型线定，数据线照着写。定下来之前，数据线不算 T5 嵌入。

**代码位置**：预处理脚本放在 `tools/data/wan21/`。读 disparity 和 T5 嵌入的数据集类也写在 `feature/model` 上。

## 2026-11-01：disparity 改为稠密（用户已批准）

完整论证见 `docs/ai-generated/dense-disparity.md`（在 `docs/proposal` worktree，尚未 commit）；提案 4.2、4.3、6.2、6.4 和术语表已按它改过。上面数据格式一节已按这里改。

1. **稠密 disparity。** 2 像素网格（240×416），每 token 64 个值。pixel unshuffle 4×4 成 16 个通道，`disp_embed = Conv3d(16→1536, 1×2×2)`，`disp_head = Linear(1536→64)`，零初始化。取代 2026-10-31 第 1 条的 60×104。备选是 4 像素网格（120×208，每 token 16 个值）。
2. **③ 每个 token 的 d** 取 64 个值的 90% 分位。所有分位数都用 `interpolation="higher"`，只取实际存在的样本值。
3. **天空不特殊处理，只截断**；P₉₀ 不排除天空。非法值：负值和 0 是天空的另一种写法，按最远处理；NaN、inf 记为无效、不算 loss（见数据格式一节 disparity 第 1 条）。
4. **时间对齐**：取离第 4k 个像素帧最近的深度帧（见数据格式一节 disparity 第 4 条）。
5. **网络输入输出用线性 d，γ 只用于分层。** 与上面"LMDB 存 γ=1 的 d"一致。
6. **a = 1/std(2d−1)**，取代 2026-10-31 第 3 条。std 在稠密 disparity 上统计，取到 0.5 的倍数后写进 `model.disparity_scale`。按本节规则在 group_0001 抽 200 段预算：std(2d−1) = 0.645（各段 P10–P90 为 0.55–0.69），1/std = 1.55，**a = 1.5**（2026-11-01 用户确认）；正式 LMDB 写完后在训练子集上复算，变化不到 0.25 就不改。两边每 token 都是 64 个值，按元素比幅度即可，不再按值个数修正。训练时看 disparity 随噪声水平的曲线（提案 7.4 第 3 项）兜底：深度明显晚于颜色就试 2a，太早且层归属错得多就试 a/2。② 和 ③ 用同一个 a。λ=1 不变：两项各按元素取均值，每 token 都是 64 个值。
