# 提议：基线 ② 的 disparity 通道怎么做

2026-11-01 · 已批准（用户，2026-11-01）· 架构图见 `docs/assets/baseline2_architecture.excalidraw`

涉及提案 4.2、4.3、4.4、6.2，以及 `feature/model` 上 `docs/ai-generated/decisions.md` 的 2026-10-31 第 1、3 条和"SpatialVID 数据格式"一节。

## 1. 结论

本方法 ③ 是在基线 ② 之上加深度调度。② 是"Wan 加一个与 RGB 联合去噪的 disparity 通道"，③ 用同一套通道和权重结构，只改训练分布和采样路径。② 的深度设计有什么缺陷，③ 都会原样继承，而且 ③ 还要靠这个通道的预测决定生成顺序。所以 ② 应当本身站得住，并尽量沿用已验证的做法；不沿用的地方要有理由。

逐项对照已发表的联合深度方法（第 3 节）后，提议三处改动：

1. **深度更稠密**（第 4 节）：每个 token 的 disparity 从 4 个值改为 64 个，与 RGB 的数值个数相同。
2. **天空不做特殊处理**（第 5.3 节）：深度换算成 disparity、归一化后直接截断到 [0,1]，不认天空，也不加 mask。
3. **时间聚合先不定**（第 5.4 节）：等看过 SpatialVID 的深度帧率再定，倾向于与相机位姿取同一帧。

另有一处与已发表方法不同但保持不改：**用线性 disparity，不取根号**（第 5.1 节）。其余设计与已发表方法一致（第 6 节）。

## 2. 术语与现状

**术语。**
- Wan VAE 把 480×832 的帧压成 60×104 的 latent 网格，下称 **latent 格**。一个 latent 格覆盖 8×8 像素。
- 一个 **token** 是 2×2 个 latent 格，覆盖 16×16 像素。RGB 在每个 latent 格上有 16 个通道，所以每个 token 有 64 个 RGB 数值。
- **disparity** = 1/深度。d 指归一化到 [0,1] 之后的 disparity：1 最近，0 无穷远。

**② 现在的实现**（decisions 2026-10-31 第 1 条）：
- disparity 作为第 17 个 latent 通道，每个 latent 格 1 个值，取 8×8 像素上 d 的 90% 分位。所以每个 token 4 个值，深度图分辨率是 60×104。
- 提案 4.3 原本更粗：每个 token 1 个值。
- 天空和无效深度都记为 d=0（decisions"SpatialVID 数据格式"一节）。

**③ 怎么用这个通道**（提案 4.4）：推理时每个去噪步，都由这个通道的预测决定每个 token 属于哪个深度层、该降到什么噪声、什么时候提交。现在每个 token 的值取 2×2 个预测值里的最大值。

## 3. 已发表的方法怎么做

| 方法 | 基座 | 深度怎么变换、归一化 | 与 RGB 怎么合 | 噪声水平 | 每 token 深度数值 |
|---|---|---|---|---|---|
| Aether | CogVideoX | 1/√clip(z, d_min, d_max)，除以整段 clip 的最大值，映射到 [−1,1]；复制成 3 通道后过 VAE | 按通道拼接，零初始化 | 共用 | 64 |
| DeepVerse | MM-DiT（AR 世界模型） | √(1/z)；按第一帧的 d_max 归一化并乘 λ 留余量；过 VAE | 按通道拼接 | 未单独说明 | 64 |
| Modality Forcing | FLUX.2-klein-9B | 像素空间，有专门的 tokenizer 和 detokenizer | 独立深度流 | 各自独立 | 像素级 |
| JointDiT | Flux + LoRA | disparity，min-max 归一化到 [0,1] | 并行分支 + joint cross-attention | 各自独立 | 未说明 |
| **② 现状** | Wan 2.1 1.3B | 1/z；第一个 chunk 的 P₉₀ 映射到 0.9；8×8 像素取 90% 分位；不过 VAE | 按通道拼接，零初始化 | 共用 | **4** |

**证据强度。** 这几篇都没有消融深度的分辨率或表示方式。Aether 和 DeepVerse 只比了"有深度 / 无深度"：

- Aether：PSNR 18.97 → 19.70，LPIPS 0.307 → 0.266。
- DeepVerse：120 帧的 subject consistency 0.768 → 0.817。

所以能说的是"已发表方法一律用稠密深度，而且稠密深度监督在视频世界模型里对 RGB 有正收益"，不能说"已证明稠密比稀疏好"。下面的理由多数是从 ③ 的需求推出来的。

## 4. 改动一：更稠密的深度

### 4.1 为什么 ③ 需要

1. **监督目标更平滑，层归属更稳。** 现在网络回归的是"8×8 像素的 90% 分位"。这是一个不光滑的统计量：一根细杆进出格子，目标值就会跳一下。改成稠密之后：
   - 网络回归的是 disparity 场本身，比分位数光滑；
   - 每个 token 的值改为从预测的 64 个值里取分位数，是一个确定的读出步骤，不用网络去学。

   ③ 的噪声只降不升（提案 4.4），层归属一旦判错就不能撤回，所以这个值的稳定性直接决定 ③ 的质量。
2. **遮挡边界可以诊断。** 提案第 9 节把"patch 跨越遮挡边界"列为 ③ 最可能出 artifact 的地方。每 token 只有 4 个值时，token 内部的远近结构已经丢了，出了 artifact 也无从分析。有 64 个值，就能看出一个 token 是不是跨着边界、近处占多大比例；以后也可以换聚合规则，不用重做数据。
3. **继承 RGB 上的收益。** Aether 和 DeepVerse 的消融显示，加入稠密深度监督后 RGB 的画质和一致性都提升了。③ 的 RGB 质量以 ② 为起点，这部分收益 ③ 会直接继承。
4. **③ 的分析需要可用的深度。** 提案 7.1 里只有本方法能做的两项（生成的 disparity 与外部深度估计器的自洽比较、按层单应变换 warp 到新视角），以及 7.4 第 3 项（disparity 准确率随噪声水平的曲线），都受深度分辨率限制，60×104 太粗。
5. **出问题时能分清原因。** ② 沿用已验证的做法，它的行为就可以用 Aether 作参照。若 ② 本身表现异常，能先排除"深度设计不合理"，不至于把问题带进 ③ 再去排查。

### 4.2 方案对比

| | A：现状 | **B：按 latent 格重排的稠密 disparity（建议）** | C：过 VAE（Aether 式） |
|---|---|---|---|
| 做法 | 每个 latent 格 1 个值 | 2 像素分辨率的 d（240×416），每个 latent 格的 4×4 个值重排成 16 个通道 | disparity 复制成 3 通道过 Wan VAE，得到 16 个通道 |
| 每 token 数值 | 4 | 64 | 64 |
| ③ 每个 token 的 disparity | 2×2 取最大 | 64 个预测值的 90% 分位，与提案 6.2 的聚合规则一致 | 每个去噪步都要把预测的深度 latent 过 VAE 解码 |
| 先例 | 无 | Modality Forcing（像素空间深度） | Aether、DeepVerse |

B 中的"重排"指 pixel unshuffle（space-to-depth）：把每个 latent 格内的 4×4 个值搬到通道维上。"unshuffle 4×4 + `Conv3d(16→1536, 1×2×2)`"在数学上就是对 2 像素网格上的 8×8 patch 做一次线性 patch embedding，与 Modality Forcing 的像素空间 tokenizer 是同一类做法。加噪、采样器、CFG、KV refresh 仍然不用改，和现在把 disparity 当第 17 个通道一样，只是从 1 个通道变成 16 个。

**不选 C 的理由：**
- **③ 的层归属会变贵。** ③ 每个去噪步都要知道每个 token 自己的 disparity。VAE latent 不是逐 token 局部的：解码一个位置要看它周围的 latent，时间上还有 4 倍压缩。于是每一步都得把整个 chunk 解码一遍，提交规则也会被 VAE 的感受野牵连。
- **Wan VAE 对深度图的重建误差没人验证过。** Aether 只在 CogVideoX 的 VAE 上说过误差小。
- B 的信息量与 C 相同，不依赖 VAE。

**折中**：用 4 像素分辨率（120×208），每 token 16 个值。更细的 1 像素分辨率（每 token 256 个值）超过了 SpatialVID 深度图的原生分辨率，等于监督插值结果，不考虑（第 7 节）。

## 5. disparity 怎么算：逐步对照

对应架构图里的绿框，从原始深度到送进网络的值。

### 5.1 用线性 disparity，不取根号（与 Aether、DeepVerse 不同，不改）

Aether 和 DeepVerse 都用 √disparity。不跟的理由：

- **它们取根号的理由不适用。** Aether 原文说这些操作"为了与预训练的 3D VAE 兼容、重建误差最小"；DeepVerse 直接沿用 Aether。我们不走 VAE（第 4.2 节），这条理由用不上。
- **线性 disparity 的 loss 权重正好对应几何误差。** 相机平移时，像素位移与 1/z 成正比。在线性 disparity 上算 MSE，同样大小的误差对应同样大小的视差误差，而视差和重投影误差正是提案 7.1 测的东西。取根号相当于放大远处：同样一个根号域上的误差，在远处对应的视差误差更小，loss 却罚得一样重。
- **远层太大的问题另有办法。** 提案 4.2 的 γ 原本同时决定表示和分层。建议拆开：网络的输入输出始终用线性 d，γ 只用于分层（按 d^γ 等距划分）。这样分层可以按提案 6.3 的统计调 γ，不影响 ②。decisions 已规定 LMDB 存 γ=1 的 d，与此一致。

我之前的建议是"表示改用 √disparity"，这里收回。

### 5.2 因果归一化（与 DeepVerse 同思路，不改）

d = clip(0.9·(1/z) / P₉₀, 0, 1)，P₉₀ 是第一个 chunk 内 disparity 的 90% 分位数，后续 chunk 沿用（提案 6.2）。不排除天空，理由和代价见第 5.3 节。

- **为什么不按整段 clip 归一化（Aether 的做法）：** 那样第一个 chunk 的值会依赖之后的内容，AR 推理时无法复现（提案 6.2）。
- **先例：** DeepVerse 也是 AR 世界模型，同样用第一帧的统计量，同样给之后更近的内容留余量。
- **与 DeepVerse 的两处不同，都有理由：**
  - **用 P₉₀，不用最大值。** disparity 的最大值是画面里最近的那个像素，一个噪声像素就能决定整段的尺度。
  - **统计量取在 disparity 上，不取在深度上。** DeepVerse 的 d_max 看起来是深度的最大值（论文写得有歧义）。有天空时深度的最大值是无穷，没有定义；disparity 的分位数总有定义。
- **只缩放、不平移：** 保证无穷远仍是 0、位移仍正比于 disparity（提案 3.2）。
- 余量取 0.9 够不够，按提案 6.3 统计的截断比例再定【待定·数据】。

### 5.3 天空：不做特殊处理，只截断（改动二）

现在的规定是天空和无效深度都记 d=0，这要求先认出哪里是天空。建议去掉这一步：深度直接按 5.2 的公式换算、截断，不认天空，也不加 mask。

- **天空自然落在最远一层。** 天空深度很大，1/z 接近 0，归一化后 d 接近 0。
- **P₉₀ 也不排除天空，代价是归一化随天空占比变化。** 天空的 disparity 接近 0，会把全画面的分位数往远端拉：天空占画面 f 时，全画面的 P₉₀ 等于非天空部分的第 1 − 0.1/(1−f) 分位。f = 0.3 时约为场景的 P86，f = 0.5 时为 P80，f → 0.9 时退到场景最远处。所以天空多的片段，场景整体被映射得更近，截断到 d=1 的 token 更多。这由提案 6.3 的截断比例统计检验，不为此加规则；比例过高时，用下面第 2 条的 z_max 截断一并解决。
- **模型不需要单独预测天空。** 推理时模型对每个位置给一个 disparity，天空自然预测成接近 0。
- **先例：** Aether 也不单独处理天空，只把深度截断到 [d_min, d_max] 再取倒数。
- **理由：** 天空 mask 是人为设计的规则，还依赖一个可靠的天空标注；截断是公式本身的一部分，不引入新规则。

**两件要看数据确认的事【待定·数据】**，确认之前按"一切正常"处理，即不做任何额外处理：

1. **深度里有没有非法值**（NaN、0、负数）。有的话，1/z 会变成 inf 或 NaN，截断后会被当成最近的一层，错得最严重。这属于数据清洗：真有这类值，就把它们记为无效、不算 loss；没有就省掉。由数据线在 `group_0001` 上统计 NaN、0、负数各占多少像素后定。
2. **天空的深度是不是足够大。** MegaSaM 给天空的深度可能是一个随意的有限值。如果天空只比场景远两三倍，归一化后会落进中间几层，层归属还会逐帧跳动。真出现这种情况，或者上一条的截断比例过高，就按 Aether 的做法给深度设一个上限 z_max（比如场景深度的若干倍），仍然只是截断，不用 mask。

### 5.4 聚合到 2 像素网格（空间不改，时间待定）

Aether 没有这一步：深度按原分辨率直接进 VAE，时间维由 VAE 压缩。我们不走 VAE，要自己定空间和时间的聚合规则。

- **空间：每 2×2 像素取 90% 分位。** 用分位数而不用平均：在遮挡边界上做平均或双线性插值，会产生既不属于前景、也不属于背景的中间值（flying pixel），这是深度图下采样的已知问题。
  - **分位数必须取实际存在的样本值**（`torch.quantile` / `np.quantile` 用 `interpolation="higher"`）。默认的线性插值同样会造出中间值：4 个值 [远, 远, 远, 近] 的 90% 分位按线性插值是 远 + 0.7·(近 − 远)。第 5.6 节 token 级的读出也一样。
  - 取 90%（偏近）是为了和 token 级的读出规则一致。只有 4 个值时，取 `higher` 的 90% 分位就是最大值。
  - SpatialVID 深度图从原生分辨率缩放到 480×832 时用最近邻，不用双线性，理由同上。
- **时间：待定，倾向于与相机位姿取同一帧。** 一个 latent 帧对应 4 个像素帧。在这 4 帧上取 90% 分位，镜头前进或物体移动时会系统性地偏近，这一点之前没有论证过。decisions 记录 SpatialVID 第一个 chunk 的 13 个像素帧只有 5 个深度帧，每个 latent 帧可能本来就只有一两张深度。建议取与相机位姿同一帧（第 4k 个像素帧），没有时取离它最近的深度帧：深度和位姿出自同一时刻，提案 7.1 的按层 warp 才对得上。等数据线看过 SpatialVID 的深度帧率再定【待定·数据】。

### 5.5 送进网络

- **pixel unshuffle 4×4：** 见第 4.2 节。
- **d̃ = a·(2d − 1)：** 映射到 [−1,1] 与 Aether 相同；缩放 a 的作用见提案 4.3。
- **a = 1 / std(2d−1)，回到提案 4.3 的原始理由。** std 在训练子集的真实稠密 disparity 上统计，取整，估计约为 2。
  - decisions 2026-10-31 第 3 条的 a=1，是因为每 token 只有 4 个 disparity 值、RGB 有 64 个，按 √N 做了修正。改成稠密后两边都是 64 个值，这个修正不再需要，按元素比幅度就够。
  - 之前推出的 a≈0.25 是想"保持 4 值实现的成形时机"，那个时机本身不是目标，作废。
  - 幅度相当时，深度图比 RGB 平滑，预计略早于颜色成形，正是 ③ 分层需要的。
  - 兜底看提案 7.4 第 3 项的曲线：深度明显晚于颜色就试 2a；深度成形太早而且层归属错得多就试 a/2；曲线正常不扫。
  - ② 和 ③ 用同一个 a。

### 5.6 推理时读出

- 网络输出换回 d：d̂ = (输出 / a + 1) / 2，截断到 [0,1]，再 pixel shuffle 回 240×416。截断是因为网络的输出不保证落在 [0,1] 内，比如天空的预测可能略小于 0。
- ③ 每个 token 的 disparity 取它 64 个 d̂ 的 90% 分位（`interpolation="higher"`，见第 5.4 节），再按 γ 分层（第 5.1 节）。

## 6. ② 的其余设计：逐项对照

| 设计 | ② 的做法 | 已发表方法 | 结论 |
|---|---|---|---|
| 噪声水平 | 与 RGB 共用 | Aether 共用；Modality Forcing、JointDiT 各自独立 | 不改。提案 4.2 的调度、4.4 的提交、4.6 的 mask 都依赖"每个 token 一个 σ" |
| 融合方式 | 按通道拼接 | Aether、DeepVerse 相同 | 不改 |
| 初始化 | 新增投影零初始化 | Aether 相同 | 不改 |
| 输出头 | 扩展输出投影 | Aether 相同；Modality Forcing 另加深度专用层 | 不改；disparity loss 卡在平台上时再考虑 |
| 额外深度 loss | 无，只有 flow matching loss | Aether 第二阶段在解码后的深度上加尺度平移不变 loss 和梯度 loss | 可选。改成稠密之后，可以直接在预测的干净 disparity 上加梯度项，不用解码 |

**不采用：**
- MMDiT 式的独立深度流：序列翻倍，attention 约 4 倍，KV cache 翻倍。
- Modality Forcing 和 JointDiT 的独立噪声：换来的是"给图像出深度、给深度出图像"这类条件生成，不是本文的问题，而且会打破"每个 token 一个 σ"。

## 7. 代价与风险

- **存储：** disparity 从 (12, 1, 60, 104) 变成 (12, 1, 240, 416)，fp16 约每样本 2.4 MB，与 RGB latent 相同，数据总量约翻倍。建议存 2 像素分辨率的原图、在训练端重排，以后换分辨率不用重做预处理。
- **SpatialVID 深度的原生分辨率是 328×584**（每段一个 zip，每帧一张 `.exr`，每段 75–90 帧；2026-11-01 在 `group_0074` 上查看）。缩放到 480×832 后，每个 2×2 像素格约对应 1 个原始深度像素，所以 B 的 240×416 基本就是原生分辨率的上限，不是在监督插值结果。深度帧和像素帧怎么对应，还要数据线核实（第 5.4 节）。
- **λ 不用改：** decisions 第 2 条是两项各按元素取均值。改完后每 token RGB 64 个值、disparity 64 个值，λ=1 时每 token 两项权重相当。
- **高维 patch 能否用 v-prediction：** JiT（Li & He 2025，arXiv 2511.13720）发现在像素空间里，patch 维数为 768 时只有 x-prediction 能学好，48 维时各种预测目标差别很小；Modality Forcing 用的也是 x-prediction。我们每 token 的输入从 68 维变成 128 维，接近低维一端，hidden 是 1536 维，预计不受影响。冒烟测试时看 disparity loss 是否正常下降。
- **会不会挤占 RGB 的容量：** Aether 和 DeepVerse 加入稠密深度后 RGB 指标都变好了（第 3 节），至少在它们的设置里没有挤占。
