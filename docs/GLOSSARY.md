# WaveFront 术语表

本表固定全项目（proposal、代码、实验记录、讨论）的说法。

- **用词以本表为准**，方法细节以 [`WaveFront_Proposal.md`](WaveFront_Proposal.md) 为准；括号里的"4.2"等指 proposal 的小节。两者冲突时，先改本表，再同步其他文件。
- **新术语先在这里登记，再使用。**
- 英文术语（chunk、token、disparity 等）在中文正文里保留原文，不翻译。
- "代码名"是新代码的命名约定；沿用 minWM 已有接口时保留其原名，并在条目里注明对应关系。

## 易混淆词速查

| 说法 | 本项目的含义 | 不要混淆 |
|---|---|---|
| 层 | **深度层**：同一 chunk 里按 disparity 划分的一组 token | transformer 层一律说"DiT 层"，不简称"层" |
| chunk | 4 个 latent 帧，自回归生成的单位 | minWM 代码里的 `block`（如 `num_frame_per_block`、`block_idx`）指的就是 chunk；而 `model.blocks` 是 DiT 层 |
| 帧 | 必须写明"像素帧"或"latent 帧" | 1 个 latent 帧对应 4 个像素帧（第 0 个只对应 1 个） |
| 步 | 上下文可能混淆时写明"去噪步"或"训练步" | 去噪步是一次模型调用加一次更新；训练步是一次优化器更新 |
| 轮 | 只用于严格逐层：一层从纯噪声去噪到干净的那 T 个去噪步 | 滚动扫描下没有"轮"，只说去噪步 |
| Stage / 阶段 | Stage 0–3 是 minWM 的训练流水线；阶段（准备、0–3）是本项目的实施计划 | 两套编号互不相关 |
| 基线 | 主结果里和本方法比较的方法：原版 minWM、① 直接续训、② 联合深度 | 本方法自己走 s=0 路径不叫基线，叫"③ 的 s=0 路径" |
| 深度 / disparity | 口语里"深度"指远近；一切定量定义都用 disparity（1 最近，0 无穷远） | 不写"深度大/小"，写"更近/更远"或给出 disparity 值 |
| σ / timestep | σ ∈ [0,1] 是噪声水平；timestep 是调度器把 σ 换算后送进网络的值 | 文档里只用 σ；代码沿用 minWM 的 `timestep` |

## 1. 基本单位

- **像素帧 / latent 帧**：视频的原始帧 / Wan VAE 压缩后的帧。F 个 latent 帧解码为 1+4(F−1) 个像素帧：第 0 个 latent 帧对应 1 个像素帧，之后每个对应 4 个。
- **原视频帧 / 标注帧**（代码名 `source_frame` / `annotation`）：SpatialVID 原视频的帧 / 其中带位姿、内参和深度的那些帧（约每 0.17–0.2 秒一个，`indexes.txt` 第 1 列是它在原视频里的帧号）。重采样到 16 fps 后的帧才叫像素帧；位姿在标注帧之间插值，深度取最近的标注帧（6.2）。
- **latent 格**：latent 网格上的一个位置。480×832 的帧压成 60×104 个 latent 格，每个覆盖 8×8 像素，RGB 在每格有 16 个通道。
- **token**：DiT 的处理单位，即一个 latent 帧上 2×2 的 patch（2×2 个 latent 格），覆盖 16×16 像素 ×（1 或 4）个像素帧。480×832 下每个 latent 帧有 30×52 = 1560 个 token。
- **chunk**（代码名 `chunk`；minWM 中叫 `block`）：4 个 latent 帧，共 6240 个 token。模型逐 chunk 自回归生成，chunk 之间 causal。
- **当前 chunk / 历史 chunk**：正在生成的 chunk / 已经生成、KV 已写入 cache 的 chunk。深度调度只作用于当前 chunk。
- **DiT 层**（minWM 中为 `model.blocks`）：transformer block。Wan 2.1 1.3B 有 30 个。
- **片段长度**：训练统一用 45 个像素帧（12 个 latent 帧，3 个 chunk）；77 个像素帧（20 个 latent 帧，5 个 chunk）的训练是可选扩展（6.2、10.4）。评测时的生成长度与训练长度分开定（7.1）。
- **注意力窗口**（minWM 中为 `local_attn_size`）：模型能看到的最近 20 个 latent 帧（含当前 chunk），约 77 个像素帧。更早的帧随 KV cache 滚动被丢掉（4.1）。

## 2. 噪声与生成的基本动作

- **σ（噪声水平）**（代码名 `sigma`）：flow matching 里 x_σ = (1−σ)·x + σ·ε。σ=1 是纯噪声，σ=0 是干净。
- **σ_i**：token i 的噪声水平。逐 token 的 σ 是本方法的前提，原模型是逐帧的。
- **σ 图**（σ map）：当前 chunk 里所有 token 的 σ_i。attention mask 和提交都只由它决定。
- **调用**：去噪网络的一次前向，记 1 次 NFE。
- **去噪步**：一次调用，加上随后对各 token 的一次更新。
- **提交 / 已提交**（代码名 `committed`）：token 的 σ 降到 0。此后它固定不变，作为其余 token 去噪的条件。每个 chunk 的最后一步强制全部提交（4.4）。
- **refresh**（minWM 中为 `rollout_refresh_cache`）：一个 chunk 全部提交后，用干净结果以 chunk 内全连接再前向一次（σ=0、d_plane=1），把 KV 写入 cache，供后续 chunk 使用（4.1、4.5、4.6）。

## 3. 深度与分层

- **disparity d**（代码名 `disparity`）：1/深度，经因果归一化到 [0,1]。1 最近，0 无穷远。天空不特殊处理，自然接近 0。disparity 通道的输入输出和 loss 用 d 本身；分层、层值和 d_plane 用 d^γ（4.2）。
- **稠密 disparity**：2 像素网格上的 d（480×832 下为 240×416），每个 token 覆盖 64 个值，与它的 RGB 数值个数相同（4.3、6.2）。
- **因果归一化**：只缩放、不平移。第一个 chunk 内 disparity 的 90% 分位数（不排除天空）映射到 0.9，后续 chunk 沿用同一个缩放系数并截断到 [0,1]（6.2）。不平移，是为了让无穷远仍是 0、位移仍正比于 disparity；不按整段视频归一化，因为那样会用到推理时还没生成的内容。
- **高分位聚合**：取一组 disparity 的高分位数（初值 90%），偏向近处。用在两处：每 2×2 像素聚合成稠密 disparity（6.2）；token 的 d 取它 64 个稠密值的高分位数（4.3）。只取实际存在的样本值，不插值，否则遮挡边界上会出现中间值。
- **disparity 幂次 γ**（代码名 `disp_gamma`）：只用于分层，分层在 d^γ 上等距；网络的输入输出不受 γ 影响。γ=1（默认）就是在 disparity 上等距；γ=0.5 即开平方根，把接近 0 的远处拉开、近层和中层变大，代价是每层覆盖的 disparity 范围不再相等。按层统计再定（4.2、6.3）。
- **深度层（层）**（代码名 `depth_layer`）：当前 chunk 内按 d^γ 等距分成 K 层（γ=1 时即按 disparity 等距）。第 ℓ 层覆盖 d^γ ∈ (1−(ℓ+1)/K, 1−ℓ/K]，最后一层包含 0（4.2）。
- **层数 K**（代码名 `num_depth_layers`）：分几层。训练时每个 chunk 从 {2, 3, 4, 6, 8} 采。不要叫 `num_layers`，那会和 DiT 层数冲突。
- **层号 ℓ**（代码名 `layer_idx`）：0 是最近的一层。
- **层值 q_ℓ**（代码名 `layer_value`）：第 ℓ 层的上沿，q_ℓ = 1 − ℓ/K。例如 K=4 时依次是 1、0.75、0.5、0.25。
- **d̂_i**（代码名 `disparity_pred`）：模型当前对 token i 的 disparity 预测：disparity 通道的输出换算成干净值，再对 token 的 64 个值做高分位聚合。
- **层归属**：一个 token 属于哪一层。训练时按伪深度真值；推理时按 d̂_i，每个去噪步更新（4.4）。
- **空层**：当前没有 token 的层。严格逐层时跳过。
- **前沿层**（代码名 `front_layer`）：按扫描方向最先、尚未提交、且非空的那一层。
- **d_plane**（代码名 `d_plane`）：前沿层的层值，即"当前扫描到哪个深度"。s=0 时约定为 1；干净 token（teacher forcing 里干净的那一半、refresh）也取 1。它先乘 1000（与 timestep 同尺度），再经 sinusoidal 编码和零初始化的 Linear，加到 `time_embedding` 的输出上，DiT 层和输出头都能看到（4.5）。

## 4. 调度

- **调度公式**：σ_ℓ = clip(σ_0 + s·(d_plane − q_ℓ), 0, 1)。同层 token 共用 σ_ℓ（4.2）。
- **σ_0**（代码名 `front_sigma`）：前沿层当前的噪声水平。
- **斜率 s**（代码名 `slope`）：相邻层的噪声错开多少。s<0 表示远→近。
- **每层步数 T**（代码名 `steps_per_layer`）：一层从 σ=1 去噪到 0 的去噪步数。s=0 时就是原模型的采样步数。
- **进度参数 c**：c = σ_0 + s·d_plane。公式只依赖这个组合；一条推理路径就是 c 从 1+s 单调降到 s/K（s>0）。
- **路径**：一个 chunk 生成过程中 σ 图的序列，由 (s, K, 方向) 和采样规则决定。
- **调度族**：所有路径的集合，一次训练覆盖。
- **调度平面**：横轴是去噪进度、纵轴是深度层的示意平面，不同路径是上面不同的轨迹（3.3）。
- **三种典型路径**：
  - **标准 diffusion**：s=0，所有层同步。
  - **滚动扫描**：0<s<K，相邻层错开 s/K 的噪声，层与层的去噪在时间上重叠。
  - **严格逐层**：s=K，前沿层去噪到底，再换下一层，更远的层保持纯噪声。规范说法就是"严格逐层"；"斜率 ∞"是 v1 的别名，"深度自回归"只作描述，不作名称。
- **方向**：近→远（s>0，前沿层是最近的未提交层）；远→近（s<0，前沿层是最远的未提交层）。

## 5. 推理规则与采样

- **目标噪声 σ_i\***：每个去噪步按 d̂_i 和调度公式算出的、token i 这一步应到的噪声。
- **只降不升**：σ_i ← min(σ_i, σ_i\*)。估计被改远的 token 暂停，等前沿追上来，不重新加噪（4.4）。
- **迟到 token**：估计被改近、目标噪声低于前沿层的未提交 token。它并入前沿层一起完成，不一步提交（4.4）。
- **逐 token Euler**：每个 token 以自己的步长 σ_i\* − σ_i 做 Euler 更新的采样器。原模型推理用的 UniPC 依赖统一时间表，不适用（5.2）。
- **草稿-提交**（v3 起不再使用）：每轮把全部剩余 token 一起去噪到底，只提交前沿层，其余丢弃、下一轮从纯噪声重来。v2 中是路径表的附加行和一个小训练分支，v3 删去（proposal 附 B）。
- **打乱层序**：层仍按深度划分，但提交的先后顺序随机排列。用于检验深度顺序本身是否重要（4.7、7.3）。
- **难度优先**（可选）：按通用难度而不是深度排序的对照。难度的 proxy 和对应的训练分支待定（7.3）。

## 6. Attention

- **严格按 σ 的 mask**：当前 chunk 内，query i 能看 key j 当且仅当 σ_j ≤ σ_i。σ 相同的 token 互相可见，s=0 时退化为 chunk 内全连接（4.6）。
- **历史 chunk 不分层**：历史 chunk 内部全连接，由 refresh 写入 cache，与生成它时走的路径无关（4.6）。
- **mask 开关**：把当前 chunk 的 mask 换成 chunk 内全连接、噪声路径不变的对照设置，用来拆开"顺序影响 attention"和"顺序影响噪声路径"两条通道（4.6、7.3）。

## 7. disparity 通道

- **disparity 通道**（代码名 `disp_embed`、`disp_head`）：每个 token 在 RGB latent 旁带 64 个稠密 disparity 值，与颜色联合去噪，共用 σ_i。经 pixel unshuffle 成 16 个通道后，`disp_embed: Conv3d(16→1536, 1×2×2)` 加到 patch embedding 输出上；`disp_head: Linear(1536→64)` 接在输出头的调制特征上。两者都零初始化（4.3）。
- **pixel unshuffle**（space-to-depth；代码 `disparity_to_channels`，逆为 `disparity_from_channels`，因子 `DISP_UNSHUFFLE`=4、通道数 `DISP_CHANNELS`=16，都在 `minwm/processors/latent.py`）：把每个 latent 格内 4×4 个稠密 disparity 值搬到通道维，得到与 RGB latent 同为 60×104 的 16 个通道；pixel shuffle 是它的逆（4.3）。
- **d̃**：送进网络的 disparity，d̃ = a·(2d − 1)。分层仍用 [0,1] 的 d。
- **a（disparity 缩放）**（代码名 `disp_scale`）：决定深度比颜色早多少成形。取 1/std(2d−1)，取到 0.5 的倍数（group_0001 实测 1.55，取 1.5），让 disparity 通道和 RGB latent 每个元素的幅度相当；先看 disparity 随噪声的曲线，再决定要不要用短 run 试 a/2 或 2a；② 和 ③ 用同一个值；不可学习（4.3）。
- **σ_eff**：缩放后深度通道的等效噪声，满足 (1−σ_eff)/σ_eff = a·(1−σ)/σ。例如 a=2、σ=0.5 时 σ_eff≈0.33。
- **λ**（代码名 `disp_loss_weight`）：disparity 那一项 loss 的权重。先定 a，再调 λ。

## 8. 训练

- **teacher forcing**：把整段视频的干净版本和带噪版本拼成一条序列，每个带噪 chunk 只能看它之前的干净 chunk 和自己（4.1）。
- **干净的那一半 / 带噪的那一半**：teacher forcing 序列的两部分。前者的 mask 与 minWM Stage 1 完全一致；后者在 chunk 内严格按 σ（5.1）。
- **路径类型**：训练时每个 chunk 采样的状态类别：s=0（25%）、严格逐层（25%）、滚动扫描（40%）、打乱层序（10%）。s≠0 的样本中 20% 取远→近（4.7）。
- **GBS**（global batch size）：每个训练步用的样本总数，等于数据并行的卡数 × 每卡 batch × 梯度累积步数。本项目取 4（6.1、8.3）。
- **已提交比例 p**（代码名 `committed_frac`）：训练时先采的进度变量（30% 取 0，其余均匀）。由它确定已提交的层数和前沿层，使训练中干净上下文的比例与推理过程匹配（4.7）。
- **exposure bias**：训练按真值分层、推理按预测分层造成的偏差。
- **分层依据切换**（可选）：训练后期改用模型预测的 disparity（一次无梯度前向）来分层，噪声仍按真值加（4.4）。

## 9. 实验与评测

- **主结果**：所有方法从同一个 minWM Stage 1 权重出发，用同一份数据、同样的训练预算各训一次，再按 7.1 评测的对比表（7.2）。
- **① 直接续训**：原模型在同一数据上续训，不做任何改动。量出"多训加换数据"本身带来多少（7.2）。
- **② 联合深度**：加 disparity 通道、训练分布固定为 s=0 的模型，结构上是原模型加一个深度输出。量出深度监督本身带来多少（7.2）。
- **③**：本方法。
- **消融**：本项目里指路径表。
- **路径表**：同一组 ③ 的权重，只换采样器走不同路径，比较一致性、动态、质量和每 chunk 调用数（7.3）。
- **NFE**（number of function evaluations）：生成一个 chunk 调用去噪网络的次数，N(s, K) = T·(1 + s(K−1)/K)（5.3）。
- **等 NFE 比较**：给所有路径同样的调用预算 N，各自反推 T，以排除"多算了几次所以更好"的解释。主结果里有一行，完整曲线在补充实验里（5.3、7.2、7.4）。
- **退化检查（s=0 等价）**：零初始化下，s=0 的前向与 minWM Stage 1 模型在浮点误差内一致。它既是单元测试，也保证训练从原模型的行为出发（4.8）。
- **层统计**：训练前在数据上统计各 K、各 γ 下每层的 token 占比，相邻 chunk 间层号跳变的比例，以及后续 chunk 截断到 d=1 的 token 比例（6.3）。
- **窗口内往返测试**：在注意力窗口内（77 个像素帧）走出去再回来的轨迹，用 RememBench 的打分方法比较出发帧和回访帧（7.1）。
- **出发帧 / 回访帧**：往返轨迹的第 0 帧 / 由估计位姿找出的、回到起点附近的那一帧（7.1）。
- **探针**：冻结 backbone，在中间层特征上训一个 DPT 头预测几何量，看特征里编码了多少几何（7.4）。

## 10. 项目管理

- **minWM Stage 0–3**：minWM 的训练流水线。Stage 0 双向 SFT，Stage 1 teacher forcing 训练 causal AR 模型，Stage 2 ODE 或一致性蒸馏，Stage 3 DMD。本项目从 Stage 1 的权重续训（4.1）。
- **阶段**：本项目的实施阶段，依次为准备、0 假设验证、1 补齐主表、2 消融与分析、3 评测（8.3）。
- **冒烟测试**：先跑几十个训练步，确认流程跑通，并实测每步耗时和峰值显存（8.2、8.3）。
- **卡时**：卡数 × 小时，用来估算算力开销（8.3）。
- **checkpoint 手术**：用一次性脚本给旧 checkpoint 补上全零的新参数，以便严格加载；参数名拼错时仍会报错（8.2）。
- **【待定·数据】**：要先看数据集才能定的事项，汇总在 proposal 6.4。
- **v1 / v2 / v3**：proposal 的版本。v1 是 commit `0f70e3a`，v2 是之后的重写版，v3 按 2–4 张 A40 的算力和新的实验结构修订（proposal 附 B）。
