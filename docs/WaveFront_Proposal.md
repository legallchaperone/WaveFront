## 1. Overview

Diffusion 的调度一直是一维的：只有噪声水平 t。我们在自回归视频 diffusion 的每个 chunk 内部加上第二个轴——深度 d——让每个 token 的噪声水平成为 (t, d) 的函数。标准 diffusion 是这个平面上的一条水平线，严格的"先近后远"自回归是另一个极端，二者之间是一个连续的调度族。3D 一致性和分层深度表示由此成为调度的副产物，不需要渲染器、3D 教师特征或外部记忆；对模型的改动只有一个标量条件和一个输出通道，斜率为 0 时严格退化为原模型。

## 2. 背景与动机

AR 视频 diffusion（CausVid、Self-Forcing、Causal Forcing 及各类交互式世界模型）逐 chunk 生成，chunk 间 causal attention 加 KV cache，是实时世界模型的主流架构。它的核心弱点是没有 3D：相机转一圈回来场景变了，遮挡边界糊，长程不一致。

给视频 diffusion 补 3D 的方法有四类：联合输出几何通道或对齐几何特征（Aether、DeepVerse、Geometry Forcing）；3D 记忆检索（WorldMem、VMem、LSM-World、WorldKV）；3D 结构噪声（EquiVDM、UniCaMo、CameraNoise）；相机位置编码（PRoPE、SCoPE）。它们都在 backbone 外面挂东西，四个口子都已拥挤。它们从未动过的对象是**生成顺序本身**。本提案改的就是这个。

## 3. 核心想法

### 3.1 直觉

普通 diffusion 里"哪些地方先变清晰"是随机均匀的。我们让它由深度决定，像雾从近到远散开：第一轮只把离相机最近的东西去噪到底，其余仍是噪声；第二轮以近处为条件生成稍远一圈；最后一轮是远景。
![[Pasted image 20261023174819.png]]
Diffusion Forcing 在时间轴上给每帧独立噪声；UniCon 用 timestep 解耦训练让成对输入各自带独立噪声调度，同一模型可以联合生成、条件生成，甚至用带噪条件做粗控制；JUICE 给图像流和文本流各自的噪声水平，把"谁是条件、谁先生成"交给采样器；Stream Forcing 把视频采样重写成按帧索引的噪声水平随机过程，在参数化空间里构造从"各帧独立"到"按时间递进"的连续训练轨迹。我们的轴与它们有一个本质区别：**深度是连续的、内生的**——每个 token 落在轴上的位置是模型自己生成出来的，而模态、条件、帧索引都是外生的离散边界。这让我们的调度族是连续的、可自适应的，代价是内容依赖的归属问题（4.3）。

## 4. 方法设计

**4.1 基座不动的部分。** 基座是 chunk-causal 的 AR 视频 diffusion。时间轴原样保留，深度调度只发生在 chunk 内部：时间 causal 是 cache、蒸馏、流式的根基，真正缺的是 chunk 内的空间结构。

**4.2 扫描方向：近→远。** 近→远（ray marching）让未生成位置带 free-space 陈述、有 anytime 性质、与粗→细同向；远→近（画家算法）的优势是背景先定。这是真实分叉，必须消融；在本设计下方向只是斜率的符号，同一组权重换采样器即可。

**4.3 token 归属由模型自己决定。** 每个 token 在 RGB latent 通道旁增加一个 per-token disparity 标量（取 disparity 的高分位数，不走 VAE），与颜色联合去噪。每个 token 的目标噪声水平由公式 σ_i 决定，其中 disparity_i 用当前的生成估计；当平面越过一个 token 的估计深度、其 σ 到 0 时该 token 提交入 cache。"迟到"的 token（估计深度被修正为更近）立即提交；最后一步强制全部提交。训练时归属由伪深度 teacher-forcing 决定，推理时由模型预测决定；这个 exposure bias 与 LLM 完全同构，用 self-forcing 类 rollout 训练兜底。

**4.4 唯一的新条件：d_plane。** d_plane 是当前扫描平面的位置（disparity 表示），告诉模型"比这更近的内容已经固定或领先，你要生成的一切都在这个平面之后"。要显式喂它，是因为光看已提交 token 猜不准扫到哪（前景为空时第 1 轮和第 3 轮无法区分）。它走 timestep embedding 的路径；斜率不必单独喂，逐 token 噪声水平已经隐含了它。把 disparity 归一化到 [0,1]（1 最近、0 无穷远），斜率 ∞、K=4 等距扫描时：

|轮|d_plane|模型做的事|采样器保留的 token|
|---|---|---|---|
|1|1|生成全部 token|disparity ∈ [0.75, 1]|
|2|0.75|生成剩余 token|[0.5, 0.75)|
|3|0.5|生成剩余 token|[0.25, 0.5)|
|4|0.25|生成剩余 token|全部剩余|

模型每轮的任务相同："把剩下的都生成出来"；保留多少是采样器的事。这与 timestep 平行：t 连续随机采所以推理可任意步数，d_plane 连续随机采所以推理可任意层数。

**4.5 训练分布覆盖整个平面。** 这是相对之前版本最重要的修改。训练时对 (σ_0, d_plane, s) 联合随机采样：σ_0 按常规 timestep 分布，d_plane 均匀于 [0,1]（并给"什么都没固定"留一定概率），斜率 s 从一个包含 0 和 ∞ 的混合分布中采（例如对数均匀加两个端点的点质量）。每个 token 的噪声由公式给出，loss 作用于全部带噪 token 的 RGB + disparity 通道。这样任何推理路径——水平线、对角线、逐行扫、反向扫——都在训练分布内，一次训练支持所有采样器。s=0 的样本就是原模型的训练样本，保证不退化。[修改意见： 训练分布要控制"干净上下文的比例"，而不是均匀采 d_plane。Patch Forcing 的教训直接适用：均匀采会让训练样本里几乎总有一大片干净 token，推理初期却什么都没有。按已提交比例采样（含比例为 0 的足够质量），后期切换到用模型自己预测的深度分组。]

**4.6 attention 按层 block-causal。** 噪声更低的 token 不看噪声更高的 token（按 σ 排序的 block-causal），使领先层的 KV 可以复用；斜率 0 时退化为全 attention。位置编码完全不动（仍是 2D/3D RoPE），顺序只由 attention mask 和噪声水平表达。

## 6. 算法流程

**训练（一次前向，开销与原模型相同）：**

1. 取一段视频及其伪 disparity，降采样到 token 网格得到每 token 的 disparity 标量。
2. 随机采 (σ_0, d_plane, s)，按 4.5 的公式算出每个 token 的噪声水平；σ=0 的 token 给真值。
3. 以 d_plane 和之前的 chunk 为条件，标准 flow-matching loss 作用于全部带噪 token 的 RGB + disparity 通道。

**推理（每个 chunk 内循环）：**

斜率 ∞ 时这个循环退化为"一层去噪到底再进下一层"（每层 T 步，共 K×T 次调用）；中间斜率时每步调用同时推进所有 token，共约 T+K 次。每个 chunk 的输出：RGB、每 token disparity、按层分组的 token 集合。

## 7. 数据

方法只需视频 + 伪深度；相机位姿方法本身不用，但评测和 camera-conditioned 基座需要，所以直接用带标注的数据集。

- **SpatialVID**（CVPR 2026）：7,089 小时动态内容，逐帧相机位姿、深度图、动态 mask。主实验用 1,111 小时的 SpatialVID-HQ 子集中相机运动大的 50–100 小时。深度自带，先直接用；若层归属在时间上抖动，再用视频一致的深度模型（Video Depth Anything、π³ 类）重标。
- **OmniWorld-Game**（ICLR 2026）：游戏环境采集，真值深度和精确相机位姿，用于回答"伪深度噪声伤害多大"。

预处理：VAE latent、T5 文本嵌入、每 token disparity 全部离线算好，训练循环不含 VAE 与 T5。

## 8. 评测与实验设计

**三层评测。**

- 通用质量保底：VBench、FVD。dynamic degree 必须与一致性指标同表——多个 benchmark 已指出空间一致性强的模型倾向于把场景做静态。
- 空间一致性（核心主张）：WorldScore 作基础分；重访类选 R2M-Bench（out-and-back、平移-旋转、闭环三种返回轨迹，相对评分）或 WBench（多轮，gated 空间一致性惩罚"靠不动刷分"）作主表；MIND、LoopNav、WorldMemBench 放附录。
- 只有本方法能做的：生成的 disparity 与外部深度估计器在生成帧上的结果做自洽比较；按层单应变换 warp 到小幅相机运动的新视角，与模型自己生成的对应帧比重投影误差；K 扫描曲线。

**核心实验是一张"路径表"：同一组权重，只换采样器。** 行是路径——斜率 0（原模型）、斜率 ∞ 近→远、斜率 ∞ 远→近、随机顺序、三到四个中间斜率；列是一致性、动态、质量、调用次数。因为训练覆盖整个平面（4.5），这张表只需一次训练，顺序消融、方向消融、v1/v2 比较全在其中，而且论证最干净：权重不变，只有路径在变。

**三个补充实验，各回答一个问题：**

1. _收益是不是多算出来的_：等 NFE 比较——固定总调用数，扫 (斜率, K) 的组合，画质量曲线。预期曲线非单调，最优点在中间。
2. _3D 到底在哪_：沿用 Geometry Forcing 的探针协议（冻结 backbone，中间层特征上训 DPT 头预测几何，目标来自 VGGT），两处修改避免 confound——对照组是"同通道、斜率 0 推理"；探我们没监督过的量（世界坐标系 pointmap、chunk 间相对相机位姿、给定相机运动下下一 chunk 的深度）。另加两条独有分析轴：按 DiT 层索引、按扫描位置画几何质量曲线。
3. _这个平面哪里可走_：disparity 预测准确率随噪声水平的曲线。深度在去噪中稳定得越早，可用的斜率范围越宽。阶段 0 顺手测。

## 9. 实施计划

**代码库：minWM**（shengshu-ai，2026.5）。四阶段齐全（双向 + 相机 SFT → causal teacher-forcing AR → causal CD → causal DMD），带相机位姿数据处理成 latent 的流程、LMDB latent 数据集、每阶段 checkpoint、序列并行和踩坑记录。备选 Causal Forcing 官方仓库（支持 Rolling Forcing）。不选 Self-Forcing：训练无数据、无相机控制，重访类 benchmark 跑不了。

**代码改动四处**：输入/输出投影加一个通道（零初始化）；逐 token 噪声水平按 4.5 公式赋值；d_plane 走 timestep embedding；attention mask 按 σ 排序 block-causal。外加 SpatialVID 的 dataloader。

|阶段|内容|8×A100 80GB 估时|
|---|---|---|
|0 假设验证|从 minWM Stage 1 AR + 相机 checkpoint 续训，480p、33 帧、3–5K 步、batch 16；同时测 disparity-vs-噪声曲线；跑简版路径表|2–3 天|
|1 完整续训|81 帧，同配置延长|3–4 天|
|2 路径表与分析|完整路径表、等 NFE、真/伪深度对照、probing|约 1 周（推理为主）|
|3 评测|三层 benchmark|2–3 天|
|4 蒸馏（可选）|minWM Stage 2/3；DMD 只作用于 RGB 通道，深度通道由阶段 1 模型自蒸馏|1–2 天|

因为路径表不再需要多次训练，总算力比上一版少约三分之二；全程约两到三周。最低配置：核心阶段 1 张卡即可，DMD 至少 2 张；建议 2–4 张保证迭代速度。阶段 0 的结论决定继续还是转向 11.3。

## 10. 风险与应对

|风险|应对|
|---|---|
|patch 跨越遮挡边界|稳健最小值归属 + 迟到容错；最可能出 artifact 的地方，优先观察|
|伪深度逐帧闪烁导致层归属抖动|视频一致深度模型 + per-video 归一化；OmniWorld-Game 真深度作对照|
|训练用真值划层、推理用预测划层的偏差累积|self-forcing 类 rollout 训练；迟到容错|
|训练分布覆盖整个平面导致每条路径的样本变稀|给端点（s=0、s=∞）和若干中间斜率加点质量；观察各斜率下的 loss|
|深度在去噪后期才稳定，可用斜率范围窄|阶段 0 的曲线提前判断；退回陡斜率 + 蒸馏|
|一致性涨、动态掉|动态指标与一致性同表；WBench gated 指标|
|假设本身不成立|阶段 0 最小代价证伪；转向 11.3|

## 11. 可选扩展

**11.1 自适应斜率与 K。** 采样器按 token 深度估计的稳定程度决定何时提交，像 ODE 求解器的自适应步长；场景简单时自动接近斜率 0。

**11.2 蒸馏。** 让 K 变大时成本不难看，并附带实时性。排在最后。

**11.3 备选方案：等变约束。** 若深度调度被证伪，转向对 KV cache 施加 SE(3) 等变约束、不用深度监督让 3D 涌现。祖先是 Equivariant Neural Rendering（ICML 2020），现代 AR diffusion 中无人做过。

## 12.  相关工作

我们的方法同时触及三个问题：生成顺序由谁决定，几何如何进入生成过程，顺序如何影响自回归视频的计算与一致性。已有工作在每个问题上都有紧密的先例；本文的位置是三者的一个特定交点。

**谁决定空间生成顺序。** 视觉自回归模型的顺序经历了从固定到学习的演变：raster 顺序（VQGAN、LlamaGen）、next-scale（VAR）、VideoAR 把预测单元当作设计轴；MAR、RandAR 用随机顺序，masked diffusion 可视为学习顺序的 AR，MaskGIT 按置信度决定先后。与此平行的是逐 token 噪声水平的路线：Diffusion Forcing 的一般形式本就是每个 token 独立的噪声水平，论文主要用于时间序列；Patch Forcing 把它落到图像 patch 上，加一个难度头让容易区域先完成、作为困难区域的上下文，并指出朴素的 patch 级独立采样会产生推理时不存在的过度知情训练状态；AsyncPatch Diffusion 让同一模型支持同步、空间自回归、修补等多条空间噪声路径；RAD 在修补任务里用逐像素噪声调度和空间噪声嵌入；MuLAN 学习依赖数据的多变量噪声调度；Spatial Reasoning Models 由去噪网络自己预测生成顺序；PONDER 学习下一步生成的位置并允许撤销。因此，"逐 token 噪声、同步与自回归之间连续过渡、内容依赖且由模型自己决定的顺序"都不是本文的新意。本文的区别在于**顺序的键**：不是难度、置信度或学习到的偏好，而是一个物理量——视线上的可见深度——它由模型与 RGB 联合预测、随生成过程更新，并用于 chunk-causal 视频 diffusion 的 chunk 内部。本文要回答的问题相应地是：对视频生成而言，物理深度是否比通用难度更适合作为顺序先验，并带来超出联合深度监督的几何一致性。这直接对应实验中"深度 vs 难度优先级"和"打乱深度对应"两组对照。

**几何如何进入生成。** 已有四条桥。其一是联合输出：Aether 联合去噪 RGB、深度与相机动作并用零初始化扩展通道，DeepVerse 把 RGB、disparity 与射线图组成联合预测状态并喂回下一步，Modality Forcing 让 RGB latent 与像素空间深度各带独立噪声、一个 checkpoint 支持联合与双向条件生成。其二是特征对齐：Geometry Forcing 把 backbone 内部表示对齐到 VGGT 的几何特征。其三是深度引导采样：DAG 从扩散中间表示预测深度并以深度一致性指导采样。其四是沿射线的分层表示：X-Ray 把沿相机射线排列的多层表面编码成类视频序列生成；World Tracing 为每个像素生成从可见表面到遮挡表面的有序点栈，并对可见层与遮挡层使用不同的噪声调度；更早的 LDI 与 MPI 是其图形学源头。此外 Channel-wise Noise Scheduled Diffusion 用不同通道的调度表达几何、材质、光照之间的生成依赖，Latent Forcing 让 latent 先于像素形成，说明"用调度让有用结构先出现"已有一般先例。本文与这些工作的区别是几何的角色：深度在本文中既是联合输出，更是**调度的键**——它决定同一帧内 RGB token 被解析的先后与依赖，而不是作为额外的重建目标或特征目标。与 World Tracing 的区别需要明说：它的"层"是同一条射线上的第几个交点，一个像素带多个表面；本文的"层"是不同像素按可见深度划分的区间，每个像素只有一个可见表面，因此本文提供的是视角相关的 2.5D 顺序先验，不保存被遮挡的内容，也不等价于 LDI 或 MPI。

**顺序如何影响自回归视频的计算与一致性。** chunk-causal 的 AR 视频 diffusion（CausVid、Self Forcing、Causal Forcing、Rolling Forcing、minWM）在 chunk 之间做 causal、在 chunk 内同步去噪，Rolling Forcing 进一步在时间轴上使用阶梯式噪声。token 级的提前提交与 KV 复用近期也已出现：ForcingBooster 让 AR 视频里的 patch 提前终止，保留其干净估计与 KV，并用 rollout 训练轻量路由器决定何时停；Speculative Forcing 按收敛程度接受中间草稿、冻结输出与 KV，只继续更新未完成区域。本文复用同一套"提交—缓存"机制，但两点不同：提交的顺序由预测深度而非收敛度或难度驱动；目标是遮挡与跨视角一致性而非自适应计算。另外 DepthArb 在图像合成中按深度顺序调制遮挡区域的 attention，这提示"顺序影响 attention"和"顺序影响噪声路径"是两条可以分开的作用通道——本文同时改动了两者，实验中必须拆开。

**正交的 3D 补法。** 3D 记忆（WorldMem、VMem、LSM-World、WorldKV、RELIC）、3D 结构噪声（EquiVDM、UniCaMo、CameraNoise）和相机位置编码（PRoPE、SCoPE）从检索、噪声分布和位置编码三个方向补几何，不改变生成顺序。它们与本文正交，可以叠加；本文基座自带 PRoPE，记忆类方法可作为后续扩展。

**定位。** 在保留 chunk-causal 结构的前提下，本文以模型联合预测的场景深度参数化 chunk 内的空间去噪路径，并通过等几何监督、等计算预算的对照，检验与可见性相关的生成顺序能否改善遮挡与跨视角一致性。贡献由三部分构成：一个闭合的、由预测深度驱动的调度—提交—缓存算法；一组排除深度监督与额外计算混淆的因果对照；以及解释该顺序何时有效、何时失败的几何机制分析。
